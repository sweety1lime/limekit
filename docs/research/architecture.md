# Архитектура: демон, окно и IPC

Как LimeKit разделён на процессы и как они разговаривают.

## Процессы

- **`renderer`** — долгоживущий демон. Ему принадлежат поверхности обоев,
  плееры libmpv, веб-поверхности, сохранённое состояние, сервер IPC, сторож
  ресурсов и значок в трее. Для автозапуска есть `limekit-daemon.exe`: тот же
  демон, но собранный как оконное приложение. Консольный `renderer.exe`,
  запущенный из ключа `Run`, открыл бы при входе окно консоли, а закрытие этого
  окна убило бы демон.
- **`LimeKit.exe`** (`apps/ui`, Tauri 2) — окно управления, которое можно
  закрыть в любой момент. Обои и трей при этом продолжают работать.

Трей принадлежит демону, а не Tauri. Иначе закрытие окна убирало бы и трей, и
управлять обоями было бы нечем. Пункт трея «Открыть» запускает окно или
выводит уже открытое на передний план.

При запуске окно:

1. подключается к демону и отправляет `ping`;
2. если никто не ответил, запускает демон как отдельный процесс
   (`DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`);
3. повторяет подключение с ограничением по времени.

Жизнь демона никак не связана с окном. Механизм sidecar в Tauri рассчитан на
дочерние процессы, которыми управляет приложение, а здесь нужно обратное,
поэтому бэкенд окна сам находит `renderer` рядом с собой и запускает его.

## Интерфейс окна

Vanilla TypeScript и Vite, без фреймворка. Это самый маленький набор
зависимостей и то, с чего советует начинать сам Tauri. Окно получает только
узкие команды Tauri, плагина shell в нём нет.

## Транспорт IPC

Блокирующие local sockets из крейта `interprocess`, без Tokio. На Windows это
named pipes, на Linux и macOS будут Unix-сокеты, сетевой стек не участвует.
Лицензия 0BSD или Apache-2.0.

Почему без асинхронности:

- клиент один, сообщения маленькие, асинхронному рантайму здесь нечего делать;
- слушатель, заблокированный в ядре, процессор не тратит;
- меньше зависимостей и проще остановка.

Имя канала строится из префикса `limekit`, мажорной версии протокола и
пользователя, так что у каждого пользователя машины свой демон. Привязка к
имени заодно работает как блокировка: второй демон того же пользователя
подняться не сможет. Демон из LimeWall 0.1 слушает имя с префиксом `limewall`,
и через него LimeKit при первом запуске просит старую версию закрыться.

## Протокол

UTF-8 JSON с префиксом длины: 4 байта little-endian, не больше 1 МиБ на кадр.
Длина в префиксе избавляет от проблем с разделителями, а JSON остаётся читаемым
при отладке.

Запрос:

```json
{
  "version": 1,
  "id": 42,
  "command": {
    "type": "play",
    "monitor": 0,
    "path": "C:\\Wallpapers\\clip.mp4",
    "quality": "balanced",
    "volume": 0,
    "anime4k": false
  }
}
```

Ответ:

```json
{
  "version": 1,
  "id": 42,
  "result": { "status": "playing" }
}
```

Ошибка — это стабильный код (`InvalidRequest`, `UnsupportedVersion`,
`MonitorNotFound`, `MediaNotFound`, `PlaybackFailed`, `Internal`) и сообщение
для человека. Каждый ответ повторяет id запроса. Чужая версия протокола,
слишком большой кадр, неизвестная команда, относительный путь к медиа и
недопустимая громкость отклоняются при разборе запроса (`Request::validate`).

Команды: `ping`, `list_monitors`, `status`, `play`, `stop`, `pause`, `resume`,
`set_volume`, `set_quality`, автозапуск, политика батареи, плейлисты и
`shutdown`. Полный список в `crates/ipc/src/lib.rs`. Крейт `ipc` содержит
только типы протокола, проверку, кадрирование и транспорт и не зависит ни от
Tauri, ни от mpv, ни от платформенного кода.

## Потоки внутри демона

Цикл приёма и по одному потоку на подключение только читают и пишут кадры.
Разобранные запросы уходят через `mpsc` в главный поток демона, которому одному
принадлежат платформенный хост и плееры mpv. У named pipes в Windows нет
таймаутов ввода-вывода, поэтому зависший клиент должен блокировать только свой
поток, а не весь демон. Одновременно открыто не больше 16 подключений.

Главный цикл просыпается по `recv_timeout`, и после каждого пробуждения
проверяет, не пора ли переключить плейлист. Отдельного потока-таймера нет.

## Платформенный слой

Всё, что зависит от Windows, лежит в `crates/platform` за трейтом
`WallpaperHost`: поверхности за иконками ([workerw.md](workerw.md)),
наблюдатель за полноэкранными приложениями, батареей и блокировкой
([politeness.md](politeness.md)), замер ресурсов, трей, автозапуск через
`HKCU\...\Run` и усиление процесса
([renderer-sandbox.md](renderer-sandbox.md)). Остальные крейты про Windows не
знают.
