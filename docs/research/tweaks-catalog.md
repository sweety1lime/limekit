# Каталог твиков и совместимость

Твики описаны данными, а не кодом: `crates/tweaks/catalog.toml` вшит в
программу, а `crates/tweaks/src/catalog.rs` и `compat.rs` его читают и решают,
что из него подходит этой Windows. Интерфейса для твиков пока нет.

## Твик как запись в каталоге

Твик — это переключатель. У него есть id вида `категория.имя` (по нему журнал
помнит, что применялось, поэтому id не меняется), название и описание на
русском и английском, метка происхождения, при необходимости ссылка на
источник, и список изменений. Каждое изменение — ключ под HKEY_CURRENT_USER,
имя значения и два состояния:

- `on` — что пишется при включении;
- `off` — значение Windows по умолчанию, обычно конкретное, иногда `"delete"`,
  когда по умолчанию значения нет вовсе.

```toml
[[tweak]]
id = "explorer.file_extensions"
title.ru = "Показывать расширения файлов"
title.en = "Show file name extensions"
description.ru = "..."
description.en = "..."
provenance = "observed"
takes_effect = "explorer_restart"

[[tweak.change]]
path = 'Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced'
name = "HideFileExt"
on = { type = "dword", data = 0 }
off = { type = "dword", data = 1 }
```

Выключить твик и отменить его — не одно и то же. Выключение пишет значения
Windows по умолчанию. Отмена через журнал возвращает то, что было до LimeKit,
а это может быть что угодно, например настройка, которую человек поставил
руками.

Состояние твика на машине — «включён», «выключен» или «другое». «Другое» — это
когда часть значений включена, а часть нет, или значения не совпадают ни с
одним из двух: их поставил человек, другая программа или обновление Windows.

## Три метки происхождения

Если брать только значения, которые Microsoft документирует, каталог почти
пуст: большую часть того, что люди хотят поменять, документация не описывает.
Поэтому каждый твик честно помечен:

- `documented` — значение описано Microsoft, например политика из таблиц CSP.
  Ссылка на источник обязательна.
- `observed` — не описано, но это ровно то, что пишет сама Windows из своих
  настроек, например галочка в параметрах папок.
- `unsupported` — приём, который Windows не поддерживает и может перестать
  понимать с любым обновлением. О таком твике интерфейс должен предупредить до
  включения.

## Совместимость

Версию программа берёт из `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion`,
это только чтение, права администратора не нужны. Нужны номер сборки и UBR
(часть после точки в 26100.4061): некоторые параметры появляются посреди
сборки, с определённого накопительного обновления. `ProductName` там на
Windows 11 до сих пор пишет «Windows 10», поэтому по нему ничего не решается.

Редакцию даёт `EditionID`, и она сводится к семействам: Home, Pro, Enterprise,
Education, Server. Pro Education считается вместе с Education, как в таблицах
политик Microsoft. Многие документированные политики работают только на
Enterprise и Education, и на Home их запись ничего не меняет, поэтому такие
твики там не предлагаются.

Для каждого твика на этой машине получается одно из состояний:

| Состояние | Когда |
|---|---|
| проверен | подходит, и его проверяли на этой сборке |
| не проверен | должен подходить, но на этой сборке его никто не проверял |
| есть в Windows | у Windows с этой сборки есть свой переключатель, в каталоге указана его страница `ms-settings:` |
| не для этой версии | сборка старше `min_build` или не младше `below_build` |
| не для этой редакции | редакция не из списка |

Проверенным твик считается на сборке, где кто-то его включил и выключил и
увидел результат, руками или в CI. У трёх твиков в каталоге проверенных
сборок пока нет, и LimeKit честно называет их непроверенными.

## Проверки каталога

`cargo test -p tweaks` проверяет вшитый каталог: id уникальны и правильного
вида, у названия и описания есть оба языка, у документированного твика есть
https-источник, пути указаны внутри HKCU без имени куста, `on` и `off`
различаются, диапазон сборок не перевёрнут, у `native_since` есть
`settings_uri`. Ошибка в данных роняет сборку в CI, а не всплывает у
пользователя.
