# Каталог твиков и совместимость

Твики описаны данными, а не кодом: `crates/tweaks/catalog.toml` вшит в
программу, а `crates/tweaks/src/catalog.rs` и `compat.rs` его читают и решают,
что из него подходит этой Windows. Экран «Твики» в окне показывает каталог с
этими состояниями.

## Твик как запись в каталоге

Твик — это переключатель. У него есть id вида `категория.имя` (по нему журнал
помнит, что применялось, поэтому id не меняется; по категории окно группирует
твики), название и описание на русском и английском, метка происхождения, при
необходимости ссылка на источник, и список изменений. Каждое изменение — ключ
под HKEY_CURRENT_USER и имя значения или системный параметр (`parameter`, см.
`tweaks-journal.md`), и два состояния:

- `on` — что пишется при включении;
- `off` — значение Windows по умолчанию, обычно конкретное, иногда `"delete"`,
  когда по умолчанию значения нет вовсе.

Многих значений на свежей Windows нет, пока человек не тронет переключатель в
Параметрах, и Windows живёт по своему умолчанию. Поле `missing` говорит, какое
это умолчание, чтобы отсутствующее значение не выглядело как «другое».

```toml
[[tweak]]
id = "explorer.file_extensions"
title.ru = "Показывать расширения файлов"
title.en = "Show file name extensions"
description.ru = "..."
description.en = "..."
provenance = "observed"
takes_effect = "new_windows"

[tweak.requires]
verified = [19045]

[[tweak.change]]
path = 'Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced'
name = "HideFileExt"
on = { type = "dword", data = 0 }
off = { type = "dword", data = 1 }
missing = { type = "dword", data = 1 }
```

Выключить твик и отменить его — не одно и то же. Выключение пишет значения
Windows по умолчанию. Отмена через журнал возвращает то, что было до LimeKit,
а это может быть что угодно, например настройка, которую человек поставил
руками.

Состояние твика на машине — «включён», «выключен» или «другое». «Другое» — это
когда часть значений включена, а часть нет, или значения не совпадают ни с
одним из двух: их поставил человек, другая программа или обновление Windows.

## Три метки происхождения

Если брать только значения, которые Microsoft документирует, каталог почти
пуст: большую часть того, что люди хотят поменять, документация не описывает.
Поэтому каждый твик честно помечен:

- `documented` — значение описано Microsoft, например политика из таблиц CSP.
  Ссылка на источник обязательна.
- `observed` — не описано, но это ровно то, что пишет сама Windows из своих
  настроек, например галочка в параметрах папок.
- `unsupported` — приём, который Windows не поддерживает и может перестать
  понимать с любым обновлением. О таком твике интерфейс должен предупредить до
  включения.

## Когда изменение видно

Сама Windows после изменения настройки рассылает окнам `WM_SETTINGCHANGE` с
названием области, например `ImmersiveColorSet` для темы. Поле `notify`
называет эту область, и LimeKit после переключения рассылает то же самое.

`takes_effect` говорит человеку, когда он увидит результат: сразу, в новых
окнах Проводника, после перезапуска Проводника или после выхода из системы.
Пока твик не проверен на сборке, это осторожная догадка, и ручная проверка её
уточняет. Что видно на Windows 10 22H2:

- Расширения, скрытые файлы и стартовая папка видны в каждом новом окне
  Проводника сразу, без перезапуска и без рассылки. Уже открытые окна остаются
  со старым видом.
- Кнопка «Представление задач» и поле поиска меняются на панели задач сразу
  после рассылки `TraySettings`.

Для настроек, которые Проводник читает только при запуске, экран предлагает
перезапустить его. Перезапуск идёт через Restart Manager, как у установщиков:
Проводник успевает сохранить своё состояние и открывает свои окна папок
заново. Окна в отдельных процессах Проводника перезапуск не трогает. Если за
десять секунд панель задач не вернулась, LimeKit запускает `explorer.exe` сам.

## Совместимость

Версию программа берёт из `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion`,
это только чтение, права администратора не нужны. Нужны номер сборки и UBR
(часть после точки в 26100.4061): некоторые параметры появляются посреди
сборки, с определённого накопительного обновления. `ProductName` там на
Windows 11 до сих пор пишет «Windows 10», поэтому по нему ничего не решается.

Редакцию даёт `EditionID`, и она сводится к семействам: Home, Pro, Enterprise,
Education, Server. Pro Education считается вместе с Education, как в таблицах
политик Microsoft. Многие документированные политики работают только на
Enterprise и Education, и на Home их запись ничего не меняет, поэтому такие
твики там не предлагаются.

Для каждого твика на этой машине получается одно из состояний:

| Состояние | Когда |
|---|---|
| проверен | подходит, и его проверяли на этой сборке |
| не проверен | должен подходить, но на этой сборке его никто не проверял |
| есть в Windows | у Windows с этой сборки есть свой переключатель, в каталоге указана его страница `ms-settings:` |
| не для этой версии | сборка старше `min_build` или не младше `below_build` |
| не для этой редакции | редакция не из списка |

Проверенным твик считается на сборке, где кто-то его включил и выключил и
увидел результат, руками или в CI. Как это делать, описано в
`docs/testing/manual-checks.md`. Пока сборки нет в `verified`, LimeKit честно
называет твик непроверенным.

## Что в каталоге и чего в нём нет

36 твиков в семи группах: Проводник, панель задач, «Пуск», советы и реклама
Windows, конфиденциальность, уведомления, оформление. Все — `observed`:
значения, которые пишут переключатели в Параметрах, в параметрах папок и в
«Параметрах быстродействия». Флаги анимации сами по себе документированы как
параметры `SystemParametersInfo`, но твик пишет ещё и `VisualFXSetting` = 3: без
него «Параметры быстродействия» остаются в режиме «Восстановить значения по
умолчанию» и продолжают показывать галочки анимации, хотя анимации уже
выключены. Это значение не документировано, поэтому и метка у твика
`observed`.

33 твика проверены на Windows 10 22H2 (19045): каждый включён и выключен,
результат виден в самой Windows, в Параметрах, в параметрах папок, на панели
задач или в окне Проводника, а после отката значения совпадают с прежними байт
в байт. Не проверены три твика только для Windows 11.

## Два хранилища у части настроек Проводника

Четыре настройки Проводника, расширения файлов, скрытые файлы, значки вместо
эскизов и флажки выбора, Windows держит в двух местах. Окна Проводника читают
значения из `HKCU\...\Explorer\Advanced`. А диалог «Параметры папок» берёт их из
собственной копии состояния оболочки (`ShellState`) и записывает обратно при
выходе с вкладки «Вид», даже по «Отмене». Если поменять только значение в
реестре, окна Проводника его учтут, но диалог покажет старое и затрёт новое,
стоит кому-нибудь его открыть.

Поэтому каждый такой твик меняет оба хранилища: значение реестра и флаг
оболочки через `SHGetSetSettings`, которым пользуется сам Проводник. Флаг в
каталоге записан как `parameter`, см. `docs/research/tweaks-journal.md`. После
этого диалог показывает то, что выбрано в LimeKit, и ничего не сбрасывает.
Остальные настройки того же диалога, например «Развернуть до открытой папки» и
«Показывать уведомления поставщика синхронизации», лежат только в реестре и
таких мер не требуют.

Одно ограничение. `SHGetSetSettings` на чтение отдаёт то, что оболочка
прочитала при первом обращении в процессе, и не замечает записей в реестр
после этого, в том числе сделанных самим LimeKit. Экран твиков читает
состояния всех твиков до любого переключения, поэтому параметр записывается как
надо. Но у твика, включённого в 0.3.0, где писался только реестр, после
обновления копия Проводника старая, а LimeKit показывает его включённым.
Выключить и включить заново в той же сессии не помогает: параметр пропускается
как «уже установлен». Помогает перезапуск окна между выключением и включением,
это проверено на Windows 10 22H2.

Чего нет и почему:

- Политик из `HKCU\Software\Policies`, например `DisableSearchBoxSuggestions`.
  Обычный пользователь может эту ветку только читать, писать в неё может
  администратор, а LimeKit работает без его прав.
- Виджетов (`TaskbarDa`). По сообщениям, в Windows 11 запись в это значение
  блокирует драйвер User Choice Protection, но кого именно он пропускает,
  источники расходятся. Сначала проверить на живой машине.
- «Новостей и интересов» в Windows 10 (`ShellFeedsTaskbarViewMode` в
  `HKCU\...\Feeds`). На тестовом ноутбуке сама Windows считает ленту
  недоступной: `IsFeedsAvailable` равно 0, причина `IDXFeedDisabledRequest`,
  виджета нет ни на панели задач, ни в её меню. Поменять значение можно, но
  результата не видно, поэтому твика нет. Вернуть его стоит, когда найдётся
  машина, где виджет есть.
- Значка дня в поле поиска («главное в поиске»). Значение
  `IsDynamicSearchBoxEnabled` = 0 в `HKCU\...\SearchSettings` на тестовой
  сборке 19045.6456 не убирает значок из поля поиска: ни сразу, ни после
  перезапуска Проводника и процесса `SearchApp.exe`, и пункт «Показать главное
  в поиске» в меню панели задач остаётся отмеченным. Где Windows 10 хранит этот
  переключатель, неизвестно. Выход из системы не пробовали.
- Анимации панели задач. Это отдельное значение реестра, которое Проводник
  читает при запуске, а твик анимаций должен действовать сразу.
- Общего выключателя уведомлений. Значения `ToastEnabled` в
  `PushNotifications` и `NOC_GLOBAL_SETTING_TOASTS_ENABLED` в
  `Notifications\Settings` не двигают переключатель «Получать уведомления от
  приложений и других отправителей» в Параметрах Windows 10 22H2: где Windows
  хранит его на самом деле, найти не удалось. Показать результат в самой
  Windows нельзя, поэтому такого твика нет. Отдельные галочки на той же
  странице, уведомления на экране блокировки и звуки, работают и в каталоге
  есть.

## Проверки каталога

`cargo test -p tweaks` проверяет вшитый каталог: id уникальны и правильного
вида, у названия и описания есть оба языка, у документированного твика есть
https-источник, пути указаны внутри HKCU без имени куста, у изменения есть
либо путь, либо параметр, у параметра `on` и `off` — это 1 и 0, `on` и `off`
различаются, `missing` не стоит рядом с `"delete"`, диапазон сборок не
перевёрнут, у `native_since` есть `settings_uri`. Ошибка в данных роняет сборку в CI, а не всплывает у
пользователя.
