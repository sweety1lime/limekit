# Импорт: ffmpeg и перекодирование GIF в mp4

GIF в LimeKit никогда не хранится и не играется как GIF: при импорте он
превращается в mp4. Так библиотека занимает меньше места, а воспроизведение идёт
тем же аппаратным путём, что у видео. Код в `apps/ui/src-tauri/src/library.rs`.

## Сложность: в LGPL-сборке нет x264

ffmpeg я беру только в конфигурации LGPL, а libx264 распространяется под GPL и
туда не входит. Вот что есть в закреплённой сборке (проверено через
`ffmpeg -encoders`):

- H.264: `h264_mf` (Media Foundation), `h264_nvenc`, `h264_amf`, `h264_qsv`,
  `h264_d3d12va` — системные или аппаратные;
- VP9: `libvpx-vp9` (BSD, программный);
- AV1: `libsvtav1`, `libaom-av1` (BSD, программные) и аппаратные варианты.

## Что выбрано

1. **Основной кодировщик — `h264_mf`**, то есть Windows Media Foundation:
   - есть в любой Windows 10 и новее, даже без дискретной видеокарты, потому что
     Microsoft поставляет программный кодировщик вместе с системой;
   - H.264 в mp4 совместим со всем и декодируется на GPU через d3d11va;
   - режим качества `-rate_control quality -quality 70`. На пробе GIF 1,38 МБ
     (480x270, 15 кадров/с) превратился в mp4 на 1,05 МБ и нормально играл за
     иконками с аппаратным декодированием.
2. **Запасной — `libvpx-vp9`** (`-crf 32 -b:v 0`, тоже в mp4), если Media
   Foundation отказал. Так бывает в N-редакциях Windows без Media Feature Pack.
3. Общие параметры: `scale=trunc(iw/2)*2:trunc(ih/2)*2` (чётные размеры, иначе
   yuv420p не собрать), `-pix_fmt yuv420p`, `-movflags +faststart`, `-an`.

ffmpeg запускается отдельным процессом с `CREATE_NO_WINDOW`, в код LimeKit он не
линкуется. Версия и хэш закреплены в [docs/third-party.md](../third-party.md),
скачивает `scripts/fetch-ffmpeg.ps1`.

## Превью

Один кадр jpg: `scale=320:-2 -q:v 4`. Для видео берётся кадр примерно на первой
секунде, а если ролик короче, то с нуля. Превью уходит в окно как base64 через
invoke, asset protocol Tauri не открывается: на одну дверь меньше.
