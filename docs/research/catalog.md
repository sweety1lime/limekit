# Каталог сообщества

Как устроен каталог обоев внутри LimeKit, почему он живёт на GitHub и что в нём
защищает пользователя. Как добавить свой пакет, написано в
[gallery/README.md](../../gallery/README.md).

## Почему Pull Request, а не загрузка из приложения

Мгновенная открытая загрузка требует сервера, автоматической проверки файлов и
людей, которые разбирают жалобы. У проекта, который один человек делает в
свободное время, ничего этого нет. Pull Request в этот репозиторий даёт
модерацию бесплатно: CI проверяет пакет, я смотрю превью и вывод CI и только
потом сливаю. Обратная сторона: новый пакет появляется в каталоге не сразу, а
после ревью.

## Как это устроено

Каталог лежит в этом же репозитории, в папке `gallery/`:

- `gallery/packs/<id>/` — сам пакет `.limekit`, превью и теги;
- `gallery/catalog.json` — индекс, который читает приложение. Он генерируется
  скриптом `build-catalog.mjs` из папок пакетов, руками его не правят, поэтому
  SHA-256 и размер в нём всегда посчитаны по настоящему файлу;
- `gallery/revocation.json` — список отозванных пакетов.

Файлы раздаются через `raw.githubusercontent.com`. Для крупных пакетов можно
использовать GitHub Releases, клиент принимает ссылки на `github.com` и
`objects.githubusercontent.com`.

Пакет добавляется так:

1. Автор собирает `.limekit` командой `renderer pack`. Флаг `--reencode`
   перекодирует видео через ffmpeg в VP9 не больше 1920 пикселей по ширине и
   убирает метаданные и звук. Это заодно стирает из файла всё лишнее, что могло
   туда попасть.
2. Автор открывает Pull Request.
3. CI (`.github/workflows/gallery-validate.yml`) проверяет, что `catalog.json`
   совпадает с тем, что генерирует скрипт, прогоняет `validate.mjs` (только
   `video` и `image`, не больше 32 МБ, обязательные поля, ограничения длины) и,
   если подпись включена, проверяет её.
4. Я смотрю превью и вывод CI и сливаю PR. После этого пакет виден всем.

## Что защищает пользователя

1. **Только видео и картинки.** Это главный рычаг: в медиафайле нечему
   исполняться. Веб- и 3D-обои в каталог не принимаются, потому что
   обфусцированный JavaScript глазами не проверить, а перекодировать код
   нельзя.
2. **SHA-256.** Клиент (`apps/ui/src-tauri/src/gallery.rs`) скачивает пакет
   только с доменов GitHub, сверяет хэш с каталогом и только потом передаёт его
   в обычный импорт со всеми проверками `crates/wpk`. На размеры ответов стоят
   жёсткие лимиты.
3. **Пакет не меняется после установки.** Скачанный пакет лежит в библиотеке
   как есть, приложение не обновляет его само. В 2026 году через Workshop
   Wallpaper Engine распространяли стилеры: элемент Workshop можно обновить
   после публикации, и взломанный аккаунт автора превращает безопасные обои во
   вредоносные. Здесь новая версия — это новый PR с новым хэшем и новое
   скачивание по кнопке.
4. **Ревью человеком.** Оно не ловит всё, но отсекает очевидное: чужой контент,
   рекламу, NSFW.
5. **Отзыв.** Об этом ниже.
6. **Изоляция во время работы.** Даже если что-то просочится, у обоев нет сети,
   моста к нативному коду и права греть процессор бесконечно. Подробно в
   [security-model.md](security-model.md).
7. **Пометка источника.** В библиотеке обои из каталога подписаны «✓ из
   каталога», остальные — «локально».

## Отзыв

`gallery/revocation.json` выглядит как `{ version, revoked: [{ id, sha256?, reason? }] }`.
`validate.mjs` следит, чтобы отозванного пакета не было в каталоге: сначала
удаляется папка пакета и пересобирается каталог, потом id вносится в список.

Клиент применяет отзыв в трёх местах:

- `gallery_apply_revocations()` при запуске окна, но только если в библиотеке
  есть обои из каталога. Без них приложение при запуске в сеть не ходит.
  Отозванные обои удаляются из библиотеки и останавливаются, если играли;
- `gallery_fetch_catalog()` при открытии вкладки «Каталог» убирает отозванные
  пакеты из выдачи и делает ту же чистку;
- `gallery_download()` ещё раз проверяет список перед установкой, на случай
  если каталог в окне устарел.

Совпадение ищется по id. У локальных импортов id — это хэш содержимого, так что
ложных срабатываний не бывает. Поле `sha256` дополнительно блокирует скачивание
по хэшу файла.

Отзыв работает по принципу fail-open: если список не скачался, галерея
продолжает работать, а отзыв применится в следующий раз. Тот, кто может
подавить загрузку этого файла, может задержать отзыв. Для онлайн-отзыва это
неизбежно.

## Подпись каталога

Клиент умеет проверять подпись Ed25519 над байтами `catalog.json`
(`catalog.json.sig`), если в `gallery/pubkey.ed25519` есть публичный ключ:
ключ вшивается в приложение при сборке. Сейчас файл пустой, так что подпись
выключена, и целостность держится на HTTPS до GitHub и на SHA-256 каждого
пакета. Как включить, написано в [gallery/README.md](../../gallery/README.md).
С подписью подделанный каталог не пройдёт даже при взломе репозитория.

## Ограничения

- Перекодирование делает автор пакета, а не CI. Пока CI этого не умеет, файл
  попадает в каталог в том виде, в каком его прислал автор.
- Ревью — это моё время. На маленьком объёме хватает, при росте понадобятся
  доверенные помощники.
- У GitHub есть мягкие лимиты на размер репозитория и трафик, за ними нужно
  следить.
- Мгновенной загрузки без PR в этой модели нет и не будет: для неё нужен
  настоящий сервер с проверкой файлов и модераторами.
